# Audi Widget Bridge for Home Assistant

An experimental Android app that hosts the **myAudi vehicle-status widget off screen** and relays its readable values to Home Assistant. It uses the official myAudi app already signed in on your phone; it does not log into Audi's API itself.

The widget **does not have to be on your home screen**. The bridge maintains its own separate instance while capture is running.

This is an independent community project, not affiliated with Audi or Home Assistant. No Audi app code, artwork, credentials or vehicle logs are distributed here. Licensed under [MIT](LICENSE).

## What it does

- Reads battery percentage, range, mileage, vehicle name, vehicle status and Audi's contact-time text.
- Sends nine sensors through Home Assistant's public **Mobile App** API, without a custom HA integration or YAML changes.
- Preserves all readable widget text/descriptions as attributes for inspection.
- Keeps vehicle status as **raw text**. It does not infer locked/unlocked from “Parked safely”.
- Captures background widget updates with a foreground service and persistent notification.
- Stores the latest pending snapshot and retries failed uploads every five minutes while capture runs.
- Offers a manual refresh action and a one-shot locked-phone refresh test. Automatically attempts refresh after **60 minutes without a successful HA transfer** while capture runs.

## Requirements

- Android 8.0/API 26 or newer, with the official **myAudi** app installed and signed in.
- A working myAudi vehicle-status widget. The parser currently targets **English labels** and **mi/km** units.
- Home Assistant with `mobile_app` enabled (included by `default_config`).
- Python 3.9+ for the one-time registration script.
- To build: Linux or macOS with Bash, JDK 17+, Android SDK platform 34 and build-tools 36.1.0. Windows users can use WSL2 with a Linux JDK/SDK. This is a command-line SDK project, not a Gradle/Android Studio import project.

## Your information goes here

**No personal credentials, addresses, vehicle data, signing keys or working connection files are included. You do not need to edit the Java source to connect your own installation.**

| Your value | Where to supply it | Stored? |
|---|---|---|
| Home Assistant base URL | Registration script prompt or `--url` | In your private registration file; used to construct the device webhook |
| Home Assistant long-lived access token | Hidden terminal prompt; optional `HASS_TOKEN` environment variable | Never written to disk or put in the APK by the script |
| Device name / phone model / Android version | Optional registration script arguments | In your own HA device registration |
| Audi account and vehicle selection | Official myAudi app and its widget setup screen | Managed by myAudi; the bridge never asks for your Audi password |
| Device-specific webhook | Generated by Home Assistant into `.private/connection.json` | Private credential; import it into the bridge |
| Signing key | Local development key or your own `SIGNING_*` environment settings | Keep private and reuse for compatible updates |

`examples/connection.example.json` contains **non-working placeholders**. The app rejects those placeholders. Generate your real file with the registration tool instead of inventing a webhook ID.

## Quick start

### 1. Build and install

```bash
git clone https://github.com/dharvey242/audi-widget-bridge.git
cd audi-widget-bridge

# YOUR local paths; replace these examples.
export JAVA_HOME="/path/to/your/jdk"
export ANDROID_SDK_ROOT="/path/to/your/android-sdk"

"$ANDROID_SDK_ROOT/cmdline-tools/latest/bin/sdkmanager" \
  "platforms;android-34" "build-tools;36.1.0" "platform-tools"
bash tests/run.sh
bash build.sh
```

Install `build/audi-widget-bridge.apk` on the phone, either by opening the copied APK or with:

```bash
"$ANDROID_SDK_ROOT/platform-tools/adb" install -r build/audi-widget-bridge.apk
```

Allow installation from the app you use to open the APK if Android asks. Builds are for sideloading; this project does not claim Google Play publishing compliance.

See [build and signing](docs/BUILDING.md) before replacing an existing installation. GitHub Actions builds use an **ephemeral development key**, so successive CI APKs may not install over one another. No stable public release-signing key is supplied.

### 2. Register YOUR Home Assistant device

From this repository directory:

```bash
python3 tools/register_home_assistant.py
```

Enter your own Home Assistant URL and a long-lived access token when prompted. In Home Assistant, tokens can be created from your user profile's security section. Use a trusted HTTPS address or a trusted private-network HTTP address; TLS verification is never disabled.

Optional phone metadata:

```bash
python3 tools/register_home_assistant.py \
  --device-name "Audi Widget Bridge" \
  --manufacturer "YOUR_PHONE_MANUFACTURER" \
  --model "YOUR_PHONE_MODEL" \
  --os-version "YOUR_ANDROID_VERSION"
```

The script creates a dedicated Mobile App registration and writes `.private/connection.json` and `.private/registration.json`. Both are credentials and Git-ignored. Rerunning with the same private directory reuses the registration. **No sample car readings are uploaded.** Sensors appear after the first real widget reading.

Home Assistant may also create a location tracker for this Mobile App registration. The bridge never sends location; disable that unused tracker in the new device's entity settings. Keep your normal Companion App registration.

### 3. Connect the phone

1. Transfer `.private/connection.json` privately to the phone.
2. Open **Audi Widget Bridge** → **Home Assistant connection** → select the file.
3. Tap **Select widget**, choose myAudi, approve Android's widget-hosting prompt, and complete any Audi vehicle-selection screen.
4. Tap **Start capture** and allow notifications.
5. Scroll to the status. A successful upload says **Connected — all sensor updates accepted**.
6. Leave capture running. The regular home-screen widget can be removed independently.

After import, the Downloads copy of the connection file may be deleted; the app stores its configuration privately with Android backup disabled. Do not share the connection file in issues, forks or chat screenshots.

### 4. Display the sensors

Look under **Settings → Devices & services → Mobile App → Audi Widget Bridge**. The default entity prefix is normally `sensor.audi_widget_bridge_`; check your actual entity IDs if you changed the device name or have duplicates.

| Sensor suffix | Meaning |
|---|---|
| `battery` | Battery percentage |
| `range` | Estimated range; HA may convert the unit according to your preferences |
| `mileage` | Odometer reading |
| `vehicle_status` | Audi's raw status text |
| `vehicle_name` | Name displayed by the widget |
| `last_vehicle_contact` | Audi's raw contact-time text, e.g. “Today, 09:15” |
| `widget_received` | Original phone callback receipt time |
| `widget_data` | Complete readable text and descriptions in attributes |
| `bridge_delivery` | Time the upload payload was prepared |

An optional native-card dashboard is in [examples/dashboard.example.json](examples/dashboard.example.json). Create an empty manual dashboard, open its raw configuration editor, and paste the file's JSON (JSON is valid YAML). Replace the entity IDs if your prefix differs. This is an example for a **new** dashboard; do not replace an existing dashboard unless you intend to.

See [Home Assistant configuration](docs/HOME_ASSISTANT.md) for complete setup and a standalone six-hour health card you can add to an existing dashboard. Repository v0.4.1 updates the HA configuration; the Android app remains v0.4.

## What triggers updates?

The bridge sends the startup snapshot and then every widget callback, including callbacks whose values are unchanged. Audi controls when it updates the widget. A five-minute timer retries **failed pending uploads**; it does not fetch vehicle data. A separate automatic refresh invokes the widget refresh control after 60 minutes without a successful HA transfer. Every successful transfer (even unchanged values) resets the countdown, as does a refresh attempt. Failed uploads do not reset it. Android sleep can delay the attempt; waking the phone checks overdue work.

See [refresh testing](docs/REFRESH.md) for the optional refresh-button experiment. Invoking the widget's refresh action is **not proof of a fresh report from the car**.

## Freshness and background reliability

- Audi's contact-time text, phone receipt time and upload time are different things. A successful upload may contain old vehicle data.
- Relative Audi text such as “Today” is kept as supplied; it is not converted into a potentially incorrect absolute timestamp.
- Home Assistant retains the latest values when uploads stop. There is no automatic server-side stale/unavailable timeout in this version. The example dashboard shows a red warning when the last bridge delivery is over six hours old; this does not establish source-data freshness.
- On Samsung, consider **Apps → Audi Widget Bridge → Battery → Unrestricted**, and exclude it from sleeping apps where supported. Menu names vary.
- Optional **Resume capture after phone restart** resumes a previously running capture after normal boot/first unlock. Force-stop and app updates can require opening the app and starting capture again.
- No permanent wake lock is held. Manufacturer policies and Android sleep can delay timers or stop the service. Overnight behaviour is not guaranteed.

## Tests and evidence

Short locked-screen capture and forwarding have been demonstrated with an English myAudi vehicle-status widget. An offscreen refresh action was also invoked while locked and produced a callback, but its source contact time was still old. This is evidence of widget interaction, **not a guarantee of forced live vehicle polling**.

The repository contains synthetic fixtures only. `bash tests/run.sh` runs parser and setup-tool tests without contacting Audi or Home Assistant. CI builds and verifies the APK. Device instrumentation instructions are in [docs/TESTING.md](docs/TESTING.md).
